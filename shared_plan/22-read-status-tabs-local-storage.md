# 22. 既読状態のローカル保存と未読・既読タブ化プラン

- 対象: `wedding-trend` の公開フィード
- 作成日: 2026-09-03
- 状態: **実装済み。本文書は実装方針と検証観点の記録である。**
- 参照: `openspec/specs/wedding-trend/spec.md` §6.5、§9.10、§10、§11
- 前提: 既読状態は閲覧者のブラウザ内だけで扱う。サーバー、DB、API、収集・公開パイプラインには保存しない。

---

## 1. 要求と現状

### 要求

フィードで記事を既読にすると、以後そのカードを「既読」タブへ移し、「未読」タブには未読カードだけを表示する。
既読状態はブラウザを再読み込み・再訪問しても維持する。

### 現状

- `src/app/page.tsx` は Server Component で `getFeedCards` を取得し、`FeedLaneClassic` と `FeedLoadMore` を描画する。
- `src/components/feed/feed-lane-classic.tsx` はカード一覧を表示するだけで、既読状態を持たない。
- `src/components/feed/feed-card.tsx` は外部記事へのリンクカードであり、クリック時の既読記録はない。
- 現時点で `localStorage` 利用箇所はない。
- `FeedCard` DTO（`src/lib/types.ts`）および DB スキーマは変更不要である見込み。

## 2. 要件・非要件

### 機能要件

1. 初期状態では、読み込み済みカードのうち未読のものを「未読」タブに表示する。
2. カードの外部リンクを開く操作で、そのカード ID を同期的に既読として記録する。外部サイトへの遷移（新規タブを含む）を妨げない。
3. 既読記録後、同一画面に留まる場合はカードを未読一覧から除き、既読一覧へ反映する。外部サイトから戻った場合も、保存済み状態に従って既読タブへ表示する。
4. タブは「未読」「既読」の2つとし、現在のタブ、件数、空状態を分かる形で提示する。
5. `localStorage` が利用不能・書き込み失敗・データ破損の場合でも、フィードの閲覧と外部リンク遷移は継続できる。状態はそのページ表示中のメモリにフォールバックする。

### 非要件

- ログイン、端末間同期、サーバー保存、管理画面での既読分析は行わない。`storage` event による複数ブラウザタブ間の同期も行わない。
- カード本文・アンカー・タイトル・URL・カード全体を `localStorage` に複製しない。**保存対象は既読カード ID のみ**である。
- 記事の取得、掲載順、`?count=` によるサーバー側の取得件数、DB・DTO・公開ゲートは変更しない。
- 「すべて既読にする」「既読を解除する」などの追加操作は本変更に含めない。

## 3. 設計判断

### 3-1. クライアント境界

`localStorage` はブラウザ API のため、`src/app/page.tsx` を Client Component 化しない。
Server Component はシリアライズ可能な `FeedCard[]` のみを新しい Client Component（例: `src/components/feed/feed-read-status-tabs.tsx`、以下 `FeedReadStatusTabs`）へ渡す。Server Component から関数 props は渡さない。

`FeedReadStatusTabs` がタブ状態、localStorage、既読化ハンドラ、カード分割をすべて所有し、その Client 境界の配下で `FeedLaneClassic` と `FeedCard` を描画する。従って `FeedCard` の外部リンクには Client 配下から `onMarkRead` を接続できる。既存の一覧コンポーネントを Server Component のまま残せない場合は、Client 配下へ取り込むか、カードのリンク部分だけを別 Client Component にする。いずれも Server → Client の関数 props を発生させない。

この境界により、初回データ取得と SEO 上のサーバーレンダリングを維持しつつ、ブラウザ固有の状態だけをクライアントで扱う。

### 3-2. 永続データ形式

キーは衝突と将来の変更を避けるため、次を用いる。

```ts
const READ_STATUS_STORAGE_KEY = "wedding-trend.feed-read-status";

type PersistedReadStatusV1 = {
  version: 1;
  readCardIds: string[];
};
```

- 値は JSON 文字列とし、カード ID 以外を格納しない。保存・比較の前にすべてのカード ID を `String(card.id)` に正規化するため、数値 ID と文字列 ID の混在でも同一性を保つ。
- 読み込み時は JSON parse、オブジェクト形状、`version === 1`、ID 配列であることを検証する。重複・空文字・非文字列は除外し、残る値も文字列として正規化する。
- JSON 破損または既知 V1 の形状不正時は空集合または正規化済み V1 として安全に扱い、可能なら V1 を上書きする。**未知 version は無視して空集合として扱い、上書き・削除しない**（将来版のデータを破壊しないため）。
- `getItem` / `setItem` は例外を捕捉する（プライベートモード、容量制限、ストレージ無効化を含む）。失敗を UI の致命的エラーにしない。読み取り不能または書き込み不能の場合、既読状態は当該マウント中のメモリだけに保持し、再訪問・戻る操作をまたぐ維持は保証しない。
- `getItem` / `setItem` は例外を捕捉する（プライベートモード、容量制限、ストレージ無効化を含む）。失敗を UI の致命的エラーにしない。
- 同一 ID の記録は Set で冪等にする。将来の肥大化に備え、実装時に保持上限・古い ID の整理要否を確認するが、本件では仕様がない限り勝手な消去はしない。

### 3-3. SSR・hydration

- 初期 HTML と JavaScript 無効時のフォールバックは、ロード済みの全カードを単一一覧として表示・利用可能にする。この HTML には既読／未読の分類もタブも出さない。
- `FeedReadStatusTabs` は hydration 完了までこの単一一覧と同じマークアップを描画し、`useEffect` で localStorage を読んで既読集合を初期化してからタブ UI と分類済み一覧へ置換する。これによりサーバー HTML と最初のクライアント描画を一致させ、誤分類 flash と hydration mismatch を避ける。
- 初期化中の一覧コンテナには必要に応じて `aria-busy="true"` を付与するが、リンクは利用可能なままにする。初期化後に `aria-busy` を外す。
- ブラウザの戻る操作／外部タブからの復帰時には、保存成功時は保存済み状態から再分類される。保存不能時は当該マウントのメモリ状態だけであり、再訪問・戻る後の分類は保証しない。

### 3-4. タブ UI とアクセシビリティ

- WAI-ARIA Tabs パターンに沿い、`role="tablist"`、各 `role="tab"`、対応する `role="tabpanel"`、一意な `id` / `aria-controls`、選択状態の `aria-selected` を持たせる。非選択パネルは `hidden` にして読み上げ・タブ順から外す。
- **manual activation** を採用する。ArrowLeft / ArrowRight は2タブ間で循環してフォーカスだけを移動し、Home / End は先頭／末尾のタブへフォーカスを移す。Enter / Space でフォーカス中のタブを選択・パネルを切り替える。クリックは即時に選択する。
- 選択中のタブだけを tab 順序 `tabIndex=0`、他方を `tabIndex=-1` とし、フォーカス位置と選択状態が視覚的にも分かるよう既存のフォーカススタイルを使う。
- タブ名は「未読」「既読」とし、件数を視覚表示・支援技術向けラベルの双方で曖昧にしない。
- 各タブに該当カードがない場合は、カードリストを空白にせず専用の空状態を表示する。未読 0 件では「すべて確認済み」、既読 0 件では「既読の記事はまだありません」など、状態を説明する文言にする。
- 既読マーク操作のために、外部リンクの意味・ラベル・`target` / `rel` の安全性を変えない。

### 3-5. 既読化の契機

- Client 境界配下の `feed-card.tsx`（またはリンク専用 Client Component）の外部リンクのクリック／キーボード起動に、`FeedReadStatusTabs` が所有する `onMarkRead(String(card.id))` を接続する。
- 既読化はリンク遷移を `preventDefault` せず、同期的に state と `localStorage` 書き込みを試みる。保存失敗時もリンクは通常どおり開く。
- カード全体のクリック面が存在する場合でも、同一操作を二重に処理しない。リンク以外の UI が将来増えても意図せず既読化しないよう、発火点は記事外部リンクに限定する。

### 3-6. ページング（`?count=`）との相互作用

- サーバーの `?count=` は取得・描画対象となる件数を決める既存契約のまま維持する。既読 ID をもとに追加取得して未読数を埋める挙動は導入しない。
- クライアントは**その時点でロード済みのカードだけ**を未読／既読へ分割する。例えば `count=20` で 20 件を読み込んだ後に 5 件を既読にした場合、未読タブは 15 件であり、21 件目以降を補充しない。
- 現行の `FeedLoadMore` は `/?count=` への通常リンクであり、クリック後は Server Component が新しいカード配列を描画する。このページング方式は変更しない。遷移後に新しくマウントされる `FeedReadStatusTabs` が localStorage を再読込し、その新しいロード済み配列を再分類する。
- 既読カードが現在のロード範囲外にある場合、その ID だけではカードを再構成できないため既読タブには表示しない。この制約を明文化し、カード全体を保存して補う設計は採らない。
- hydration 後の「もっと見る」は未読タブにのみ置き、表示中件数は総ロード数ではなく未読の分類後件数とする。既読タブには件数表示・補足・導線を置かない。SSR/JS 無効時の単一一覧では従来どおり総ロード済み件数と導線を維持する。
- `?count=` の追加ロードで初めて届くカードは、保存済み既読 ID に一致しない限り未読に入る。既読数が少ないことを理由に既読タブへ追加カードを補充しない。

## 5. テスト計画

実装時は既存の `tests/ui/feed-lane.test.tsx`、`tests/ui/feed-card.test.tsx` を中心に拡張し、状態ユーティリティを分離した場合は専用テストを追加する。

1. 正常系: V1 の既読 ID を読み込み、`String(id)` 正規化で未読・既読へ正しく分割する。重複 ID は1件として扱う。
2. 破損復旧: 不正 JSON、既知 V1 の誤った shape、ID配列内の不正値で例外を出さず、空集合または正規化結果にフォールバックする。未知 version は無視し、既存値を上書きも削除もしない。
3. 保存失敗: `getItem` が throw、`setItem` が throw、get は成功するが set が失敗する場合に、カード表示と外部リンク起動が継続し、当該マウント中のメモリ状態では既読分割が反映されることを確認する。
4. Client 境界: Server 側が `FeedCard[]` だけを渡し、既読化関数とリンク処理が Client 配下に閉じていることをコンポーネントテストまたは型検査で確認する。
5. タブ操作: 既定タブ、クリック、manual activation の ArrowLeft / ArrowRight / Home / End によるフォーカス移動と Enter / Space による選択、`aria-selected` / `aria-controls` / `tabpanel` / `hidden` / tabIndex の対応、両方の空状態を確認する。
6. クリックとキーボード起動: 外部リンクのクリックおよびキーボード起動で ID が保存され、未読タブから既読タブへ移る。`preventDefault` を用いず、リンク URL・`target`・`rel` を維持する。
7. hydration と再訪問相当: 初期 HTML が単一フォールバック一覧であること、初期化後に保存済み ID で分類されること、hydration 警告が出ないことを確認する。
8. ページング: `/?count=` の通常リンク遷移後に Server が描画した新しいカード配列を、Client が localStorage 再読込後に再分類することを確認する。ロード済み範囲だけを分割し、対象外を補充取得しない。
   未読タブだけに分類後件数・補足・導線が出て、既読タブにはそれらが出ないこと、追加 ID が未読に入ることも確認する。
9. 法務表示回帰: `originalTitle` の逐語表示、`sourceName` 常時表示、著者がある場合の表示、外部リンク CTA、本文・`originalExcerpt` を保存／表示しないことを既存テストに残す。

新しい検証を追加した場合は、保存失敗や破損データの変異で実際に失敗することも確認し、単に緑になるだけで済ませない。

## 6. Definition of Done

- 既読カード ID のみが V1 形式でブラウザに保存され、再読み込み後もロード済みカードが正しく既読タブに入る。
- 未読・既読タブがマウス、キーボード、支援技術で操作・理解でき、両方の空状態がある。
- 外部リンクを妨げずに既読化でき、保存不能でも閲覧不能にならない。
- `?count=` の意味とサーバー取得範囲が変わらず、未読補充の追加ネットワーク要求を行わない。
- 「もっと見る」は hydration 後の未読タブに限り表示し、表示中件数は未読の分類後件数である。既読タブへ追加カードを移さず、追加された未保存 ID は未読に分類される。
- `spec.md` が実装と同時に更新され、本文非生成・非永続化、逐語タイトル、出典／著者、アクセス規律の法務不変条件を弱めない。
- 関連する lint、type-check、UI テスト、coverage tier、spec-refs、security、smoke test を実行し、差分と実際のタブ挙動を確認する。

## 7. リスクと対策

| リスク                                                               | 対策                                                                                                 |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| SSR とブラウザ保存状態の差で hydration mismatch や一瞬の誤表示が出る | Server Component を維持し、クライアント初期化完了までの表示を明示して `useEffect` で安全に反映する。 |
| localStorage が壊れている／使えない                                  | parse と read/write を例外安全にし、空集合・メモリ状態へフォールバックする。                         |
| 保存対象が将来カード内容へ拡大し、法務制約に触れる                   | V1 型を ID 配列に限定し、spec とテストで「カード本文・全体を保存しない」を固定する。                 |
| 既読が増えると未読タブが短くなり、意図せず追加取得したくなる         | `?count=` は取得上限のまま、ロード済みカード限定の分割であることを仕様・テストに明記する。           |
| クリックハンドラが外部遷移を妨げる                                   | 同期的な best-effort 記録のみを行い、`preventDefault` や await による遷移制御をしない。              |
